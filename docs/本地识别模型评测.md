# 本地语音识别模型评测（2026-09-25）

结论：内置 **X-ASR 中英文流式带标点模型（480ms 块，int8）**，设成新装默认的识别服务，叫「本地识别」。

- **能认的内容**：中文、英文和中英夹杂一个模型全包，自带标点和大小写。
- **准确率**：在四套真实录音上，都比其他本地模型准；中文和英文会议也比现在用的豆包 2.0 准。
- **速度**：说完一个词约 0.5 秒出现在屏幕上。
- **资源**：CPU 只要实时的 5% 到 13%，内存多占 240 MB。
- **体积和许可**：解压后 170 MB，Apache-2.0 许可，可以商用。

豆包和 OpenAI 留作可选的云端识别。

## 怎么测的

**测试录音**：从 Hugging Face 取真实录音，每套拼成 2 到 3 分钟的连续音频，16k 单声道。

| 测试集 | 内容 | 时长 |
|---|---|---|
| AMI | 英文会议，多人讨论，口语多 | 185 秒 |
| Earnings-22 | 财报电话会，带口音的英文，电话音质 | 190 秒 |
| ASCEND 中文 | 香港大学生的中文对话 | 122 秒 |
| ASCEND 中英夹杂 | 同上，一句里混着英文单词 | 122 秒 |

**怎么跑**：
- 所有本地模型都用软件里已经打包的 sherpa-onnx 1.13.8，2 个线程。
- 流式模型按 100 毫秒一包喂，记下每个字从说出来到出现在屏幕上的时间。
- 非流式模型用 silero VAD 按停顿切句，每句整句识别。
- 豆包 2.0 用软件里的识别模块，按实时速度送同样的音频。

**机器**：Mac mini M4；Windows 笔记本 Ryzen 9 8945HX。

**指标**：英文算 WER（Whisper 的英文归一化），中文和夹杂算 MER（汉字一个字一个单位、英文一个词一个单位）。

测试脚本在 `scripts/asr-bench/`，用法写在 `bench.mjs` 开头。

## 英文

「出字延迟」的算法看模型类型：
- **流式模型**：一个词说完到出现在屏幕上的时间，写的是中位数 / 90% 分位。
- **非流式模型和豆包**：整句说完到整句文字出来的时间。这类模型一句没说完之前屏幕上没有字。

「CPU」是 M4 上 2 个线程的实时率，数字越小越省；0.1 表示认 1 分钟的音频要 6 秒计算。

## Windows 上的速度

测试音频是 Earnings，Ryzen 9 8945HX，数字是实时率，越小越省。

| 模型 | 1 线程 | 2 线程 | 内存 |
|---|---|---|---|
| **X-ASR 480ms** | **0.059** | 0.058 | 240 MB |
| X-ASR 160ms | 0.134 | 0.134 | 240 MB |
| Parakeet v2 | 0.099 | 0.073 | 680 MB |
| SenseVoice 2024 | 0.050 | 0.035 | 300 MB |
| Nemotron EN 560ms | 0.327 | 0.241 | 700 MB |
| Nemotron 3.5 560ms | 0.305 | 0.230 | 715 MB |

- **准确率两边一致**：Windows 和 Mac 上是同一个模型，X-ASR 在 Earnings 上 8.6% 到 8.8%，Mac 上 9.0%。
- **线程数**：X-ASR 480ms 单线程就够。开会时对方和我两路同时认，也只占一个核的 12% 左右。
- **普通笔记本**：我猜会慢 2 到 3 倍，仍然很宽裕。

## 为什么是 X-ASR 480ms

- **准确率**：中文、英文、中英夹杂都是本地模型里最准的，一个模型全包。
- **边说边出字**：一个词说完约半秒上屏。非流式模型（Parakeet、SenseVoice）要等整句说完才出字，想边说边出字只能反复重算正在说的这句，CPU 要多花好几倍。
- **CPU**：两路一起开，和 Zoom 同时跑也不紧张。
- **体积**：170 MB。Parakeet、Nemotron 都在 630 MB 以上。
- **许可**：Apache-2.0。
- **160ms 版不选**：出字快 0.2 秒，但准确率低 1 到 2 个点，CPU 多一倍。

## 已知的问题

- **专有名词会听错**：Bonferroni 听成「bond for only」，scikit-learn 听成「sicket learn」。
  - 靠已有的 AI 纠错改：纠错请求里带着项目术语表。
  - sherpa 的热词不稳：开到 3 分以后 ROC curve、WebVision 对了，Bonferroni 却变成「Bonferrection」，所以没开。
- **中文句末常常没有标点**：X-ASR 的句末标点要等下一句开口才出来，中文在停顿里始终不出。
  - 软件把下一段开头多出来的标点去掉。
  - 判断「对方在提问」看的是疑问词、句尾的「吗」「呢」、助动词开头，不依赖问号，所以自动答题不受影响。
- **数字可能偏乐观**：我猜 X-ASR 的训练数据里有 AMI、ASCEND 这些公开数据集的训练部分，它在这几套上占了点主场优势。真实会议里和豆包的差距可能没这么大，要在真机上开几场会再看。
- **项目很新**：X-ASR 2026-05 才发布，技术报告还没出。以后每次升级 sherpa-onnx 都要在 M4 上重跑一遍 `scripts/asr-bench`（ORT 升级曾让 zipformer 流式在 M4 上出乱码）。

## 在软件里怎么接的

- **识别在哪跑**：在 utilityProcess 里（`src/main/asr/localHost.cjs`），不卡主界面。
  - 对方和我两路共用一个进程、一份模型，模型常驻，下一场会直接用。
  - 选了本地识别时，软件启动 3 秒后先在后台把模型加载好。
- **分句**：sherpa 判断到 0.8 秒停顿就定稿一段；定稿给出这一段在音频里的起止时间，声纹和串音判断照旧能用。
- **长段落**：一口气说超过 15 秒（讲课常这样），在下一个句号、问号处先定稿前半段，不会把句子或单词从中间劈开；一直没有句末标点时 5 分钟才强制切。0.5.1 以前是 20 秒强制切，Windows 真机上出现过「k fold cro｜ss validation」。
- **意外退出**：进程退出会自动重开接着认。电脑太忙跟不上时（积压超过 4 秒）提醒一次。
- **模型怎么进安装包**：不进 git。`npm run models` 下载并校验 SHA-256，打包前 `scripts/sherpa-native.mjs` 自动下载，装进 Resources/models/xasr。
- **老用户升级**：还没配好识别 Key 的老用户换成本地识别；已经填了豆包或 OpenAI 的不动。
