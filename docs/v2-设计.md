# 会议字幕 v2 设计与接口约定

用户（贾宗翰）自己也要用：面试、跟导师开会、给老板讲项目。v1 已有：抓系统声音 → 识别（OpenAI gpt-live-transcribe / 豆包）→ 悬浮字幕 + 全局快捷键 → 逐句存档 → 会后纪要。v1 架构见根目录 `CLAUDE.md`，先读它和现有代码再动手。

## v2 要加的东西（用户原话整理）

1. **两路声音**：除了电脑声音（对方），默认也录麦克风（我）。录一段声纹，识别哪句是我、哪句是别人。外放时麦克风会串进对方的声音，用声纹 + 文本比对把串音滤掉；面对面（只有麦克风）时，声纹不匹配的算「对方」。
2. **实时字幕走豆包**（用户自己的设置里切到 volc；代码默认值不变，朋友那边仍默认 OpenAI）。
3. **翻译、会后纪要、答题走 ChatGPT 订阅额度**：应用内「用 ChatGPT 账号登录」（OAuth），请求发到 Codex 后端 Responses API。
4. **AI 实时答题**：对方一问完（字幕定稿且判断是问题），屏幕右侧的答题框马上流式给出我可以照着说的回答。可以带上当前屏幕截图（我在共享屏幕讲项目时，老板问「这一块」）。也能手动快捷键让它回答刚才的问题。目标：问题说完到答案第一个字 ≤ 3 秒。
5. **术语悬停解释**：字幕里的专业术语加下划线，鼠标停在上面弹出一句话解释。
6. 字幕窗和答题框都对屏幕共享隐藏（setContentProtection），显示/隐藏快捷键一键全藏全显。

## 全局约定（所有 agent 都要守）

- 纯 JS，无打包器；主进程 ESM，preload `.cjs`；注释少而中文，风格跟现有代码一致。
- 界面文字简体中文。**任何文字里都不许出现破折号（— 和 –）**，用逗号、冒号、句号。
- 不 commit、不 push（主会话统一提交）。
- 密钥：`OPENAI_API_KEY` / `VOLC_ASR_APP_ID` / `VOLC_ASR_ACCESS_TOKEN` 放环境变量，只在命令里用，别打印、别写进仓库或测试夹具。
- ChatGPT 订阅测试：`~/.codex/auth.json` 里的 `tokens.access_token`、`tokens.account_id` **只读**使用（约 3 天后过期）。**绝对不要用它的 refresh_token 刷新**（刷新会轮换 token，把用户本机 Codex CLI 登出），不要复制进仓库或应用设置。
- 不要用扬声器放声音（afplay/say 直接播放）影响用户，除非你的任务明确写了；需要测试音频就用 `say -o x.wav --data-format=LEI16@16000` 生成文件。
- 不要打开麦克风录真实环境声音。
- `npm test` 必须一直通过；纯逻辑写单测放 `test/*.test.js`。
- 测试时用隔离目录：`MEETCAPTION_USERDATA=<scratch>/ud`，设置里 `saveDir` 也指到 scratch，别写用户的「文稿/会议字幕」。
- Electron 开发版从终端启动时继承终端的屏幕录制、系统录音权限，可以直接测 desktopCapturer 和 audiotee。

## 模块 A：ChatGPT 订阅通道（`src/main/llm/`）

文件：`src/main/llm/chatgptAuth.js`、`src/main/llm/chatgpt.js`、`src/main/llm/openaiCompat.js`（由现有 `src/main/llm.js` 挪过来并支持图片）、`src/main/llm/index.js`（门面）。旧的 `src/main/llm.js` 保留一个转发，别让现有 import 断。

```js
// index.js：所有调用方只用它
export async function complete(settings, auth, {
  model,          // 'fast' | 'smart' | 'answer' | 具体模型名；fast=llmFastModel，smart=llmSummaryModel，answer=llmAnswerModel
  system,         // string
  messages,       // [{ role: 'user'|'assistant', content: string | Array<{type:'text',text}|{type:'image',dataUrl}> }]
  effort,         // 'none'|'low'|'medium'，各提供方自己映射
  maxOutputTokens,
  json,           // true：要一个 JSON 对象
  signal, timeoutMs,
  onDelta,        // (累计全文) => void，给了就流式
}) → Promise<string>
export function llmStatus(settings, auth) → { provider, ready, label, reason }
```

- `chatgptAuth.js`：`class ChatGPTAuth extends EventEmitter`，构造 `{ file }`（userData/chatgpt-auth.json，0600；Windows 用 safeStorage 加密，Mac 不用），方法 `status()`、`login({ openExternal })`（PKCE，本地回调 `http://localhost:1455/auth/callback`，超时 5 分钟，成功页面给中文提示）、`logout()`、`getAccessToken()`（快过期就用**自己的** refresh_token 刷新）。OAuth 常量（client_id、scope、额外参数、token 端点、account_id 从哪个 claim 取）去 openai/codex 源码（codex-rs 的 login 模块）核实，别凭记忆。开发自测支持环境变量 `MEETCAPTION_CHATGPT_AUTH=codex`：只读 `~/.codex/auth.json` 的 access_token/account_id，不刷新。
- `chatgpt.js`：Responses API，`https://chatgpt.com/backend-api/codex/responses`，SSE 流式。核实 Codex 后端需要的请求头和必填字段（instructions、store:false、stream 等），参考 codex 源码或 Docker Agent / OpenCode 的实现。支持图片输入（input_image，data URL）、reasoning effort、输出长度。
- **实测并在交付里报数字**：gpt-5.6-luna、gpt-5.6-terra 各在「纯文本」和「带一张 1600px 截图」下的首字延迟和总耗时（各 3 次），以及 reasoning effort 对延迟的影响。据此给出答题默认模型和 effort 的建议。

## 模块 B：声纹（`src/main/audio/voiceprint.js`）

- 用 sherpa-onnx 的 Node 包（Node-API，Electron 里不用重编）+ 说话人向量模型（3D-Speaker 或 WeSpeaker，≤ 30MB，中英文都行）。选型、Mac arm64/x64 和 Windows x64 的包是否齐全都要核实。模型打进安装包（朋友可能在国内，别首次运行再下载），electron-builder 的 files / asarUnpack 要写对，给出需要改的配置片段。
- 接口：
```js
export async function loadVoiceprintModel() → { embed(float32At16k) → Float32Array(已归一化), dim, modelId }
export function cosine(a, b) → number
export function pcm16ToFloat32(buf) ; export function resample(float32, fromRate, toRate)
export class VoiceprintStore { constructor(file); load() → { embedding, modelId, seconds } | null; save(profile); clear() }
export function enrollFrom(float32At16k, model) → profile   // 太短（< 6 秒有效语音）或太安静要报错
```
- 实测：用 macOS 不同的 `say` 声音（至少 3 个英文 + 1 个中文声音）生成音频，某个声音注册，报告同一声音和不同声音的相似度分布，给出阈值建议；测单段 1 秒、3 秒、8 秒的区分度和耗时。在 Electron 主进程里真的加载一次（写个最小脚本 `ELECTRON_RUN_AS_NODE` 不算，要在 `electron .` 的主进程环境里验证）。

## 模块 C：AI 答题（`src/main/assist/` + `src/renderer/answer/` + `src/preload/answer.cjs`）

- `question.js`：`isQuestion(text)`，英文和中文都要覆盖：问号结尾、疑问词开头、「tell me about / walk me through / could you explain / what do you think」这类祈使式提问、中文「吗/呢/什么/怎么/为什么/能不能」。单测覆盖正反例。
- `screen.js`：`captureScreen({ maxWidth: 1600, quality: 0.8 })` → `{ dataUrl, width, height, ms }`；用 desktopCapturer 取鼠标所在显示器；Mac 没权限时抛 `code: 'no-permission'` 的错误。我们自己的字幕窗、答题框设了 content protection，不会出现在截图里（顺便验证）。
- `assistant.js`：`class Assistant extends EventEmitter`，构造 `{ complete }`（注入 A 模块的 complete，方便单测 mock），方法 `ask({ question, transcript, context, profile, withScreen, answerLang, reason })`；新问题来时取消上一个还在生成的；事件 `'answer'`：`{ id, question, text, done, error, reason, timing: { screen, firstToken, total } }`。截图和组 prompt 并行做。答题 prompt：给我能直接说出口的回答（第一人称、口语、短句），最前面一行很短的中文要点，然后英文（或跟随提问语言）2 到 4 句；拿不准就给诚实的回答框架；用上屏幕内容和「我的资料」。
- 答题框窗口（renderer/answer + preload/answer.cjs）：独立的置顶窗口，默认在屏幕右侧、字幕上方；样式和字幕窗一个体系（深色半透明）；卡片列表显示「问题 → 回答」，最新在最上，流式出字，显示耗时；按钮：重新回答、复制、收起；调整位置模式下可拖动和改大小。IPC 约定：main→renderer `answer:update`（answer 对象）、`answer:config`；renderer→main `answer:ready`、`answer:regenerate`(id)、`answer:doneEditing`、`answer:setBounds`({x,y,width,height})。窗口创建代码写成一个函数 `createAnswerWindow({ preload, page, bounds })` 放 `src/main/assist/answerWindow.js`，主进程接线时调用。

## 模块 D：术语悬停（`src/main/prompts.js` 的一部分 + `src/renderer/overlay/`）

- 在 prompts.js 新增 `enhanceMessages({ sentence, previous, target, translate, context, keywords })` 和 `parseEnhance(text)`：一次请求同时拿译文和术语，JSON `{"tr": "...", "terms": [{"term": "原文里的原样片段", "explain": "一句中文解释，≤ 40 字"}]}`；translate=false 时不要译文；没术语就空数组；解析要容错（代码块包裹、多余文字）。单测。
- overlay 渲染：句子里出现的 term 加虚线下划线；鼠标停留 300ms 弹出解释框（在字幕上方），移开消失。字幕窗平时是点击穿透的：主进程要改成 `setIgnoreMouseEvents(true, { forward: true })` 并把窗口加高一截透明区域给解释框用。把主进程需要改的地方写进交付说明（不要自己改 main.js）。控制窗口的实时记录里同样的术语用 title 或同款气泡显示解释（写说明，由界面 agent 做）。

## 接线（E1 主进程，E2 界面）

- E1：settings、engine（麦克风默认开；豆包 utterance 带 start/end 时间，按时间从该路音频环形缓冲取片段算声纹；OpenAI 路用门限的 turn 边界；声纹不匹配的 mic 段：最近 10 秒 system 段文本相似就判为串音丢掉，否则算「对方」；翻译改成 enhance 一次拿译文和术语，只对 who=other 的句子做；对方的定稿问题触发 Assistant）、main（答题窗、字幕窗 forward 鼠标、快捷键：显示隐藏一键控制字幕和答题框、提问快捷键；ChatGPT 登录/声纹录制的 IPC）、preload/control.cjs 加 API、selftest 加假音源：`--fake-system=a.wav --fake-mic=b.wav` 用文件代替真实采集（按实时速度喂），方便无设备端到端测试。
- E2：控制窗口界面：AI 服务里加「用 ChatGPT 账号登录」（显示账号和套餐、退出）；声纹卡片（录制 12 秒，给一段朗读文字、倒计时、音量条，完成后显示「已录制」和重新录制/删除）；AI 答题卡片（开关、自动回答、带屏幕截图、我的资料大文本框、回答语言、提问快捷键）；术语解释开关；实时记录里显示我/对方、问题标记、术语解释；首次使用引导更新。

IPC 新增约定（E1 实现，E2 调用）：
- invoke：`chatgpt:status`、`chatgpt:login`、`chatgpt:logout`、`voiceprint:status`、`voiceprint:enroll`(seconds)、`voiceprint:clear`、`assist:askLast`
- 事件：`chatgpt:status`、`voiceprint:progress` `{ phase: 'recording'|'processing'|'done'|'error', level, secondsLeft, error }`、`assist:answer`（同答题框的 answer 对象，控制窗口也显示一份）
