# 会议字幕 v4：双语意群对照、难词两边标、课堂模式

在 v3（Raycast 风格界面、首次引导、项目）之上加。用户原话：老板用英语问我，下面有一行中文翻译我就更能看懂，但不能是大长段；中英对照看得慢，要是能按段落或语法结构用不同颜色标出来，我更好看清结构；难的词在中英两边都高亮或下划线，更好定位、更好看懂；不只是开会，上课时老师在前面讲，我打开软件，要有课堂模式，Get笔记（得到大脑）的听课模式做得很好，可以参照。

全局约定同 `docs/v2-设计.md`（不许破折号、不 commit、密钥规矩、不放扬声器、不开真实麦克风、npm test 通过、测试用隔离目录）。

## 一、双语意群对照

### 数据

enhance 一次请求拿到整句译文、意群对齐和术语（替换 v2 的 `{tr, terms}`）：

```json
{
  "tr": "完整中文译文",
  "chunks": [{ "en": "英文原句里的原样片段", "zh": "tr 里的原样片段" }],
  "terms": [{ "term": "英文原样片段", "zh": "tr 里对应的原样片段（没有就空）", "explain": "一句中文解释，不超过 40 字" }]
}
```

- `chunks` 按英文顺序，首尾相接覆盖整句（标点可以不算），一句 2 到 5 块，按意群切：主干、从句、介词短语、插入语各自一块，短句可以只有 1 到 2 块。`zh` 必须是 `tr` 里的原样子串；中文语序和英文不同没关系，渲染时按 `zh` 在 `tr` 里找位置。对应的中文在 `tr` 里不连续时，`zh` 可以是几段的数组（同一个颜色）；模型给了一段拼起来的 `zh`、`tr` 里找不到时，parseEnhance 按译文里能找到的最长片段拆开（最多 3 段）。
- 译文要短：口语化，一句英文对一句中文，不加解释性扩写。
- `parseEnhance` 容错：chunk 或 term 在原文、译文里找不到的就丢掉，不影响其它；全坏了退回 `{tr:'', chunks:[], terms:[]}`。旧数据（只有 tr、terms）照样能显示。
- 存档：`seg.sentences[i] = { text, tr, chunks, terms }`。

### 显示（字幕窗、主窗口实时记录、会议详情的字幕记录都一样）

- 每句英文下面紧跟它的中文，一句一对，不拼成大段。
- 意群颜色：4 种柔和、在深色半透明底上都清楚的颜色循环（比如蓝、琥珀、绿、粉），英文片段和它的中文片段用同一种颜色（文字颜色或下方细色条，挑更好读的，两种都截图比较）。没有对齐信息的部分用默认颜色。
- 难词：英文 term 虚线下划线，中文里对应的 `zh` 也加同样的下划线（或淡色底高亮），悬停任一边都弹同一个解释气泡。
- 设置（字幕与答题框分区）：「意群颜色对照」开关，默认开；关掉就退回单色。
- 共用渲染代码放 `src/renderer/shared/bilingual.js`（纯浏览器脚本，挂 `window.bilingual`），字幕窗和主窗口都用它，只用 textContent 拼 DOM。

## 二、模式：会议、面试、课堂

- 开始时选模式：`start({ projectId, mode })`，`mode` 是 `meeting | interview | class`。项目有默认模式 `project.mode`（新建项目时选，之后可改）；开始按钮的下拉里可以临时换。`session.mode` 存档。
- 会议：v3 现在的行为。
- 面试：AI 答题默认开且自动回答，答题框更显眼；其它同会议。
- 课堂：见下一节。

## 三、课堂模式

参照 Get笔记（得到大脑）的听课：边听边转写，AI 边整理笔记，课后出结构化课堂笔记，能拍板书或截课件。

- **声音来源**：课堂分「教室现场（麦克风）」和「网课（电脑声音）」两种，开始时选，记在项目上。教室现场时麦克风是主声源：录了声纹的话，像我的算「我」（我在课上提问），其余算「老师」；没录声纹就都算「老师」。网课时电脑声音是「老师」，麦克风按 v2 的规则。课堂模式下对方的称呼显示为「老师」。
- **AI 答题**：课堂默认关自动回答（老师点名提问时可以用快捷键手动让 AI 答）。
- **实时笔记**：每累计约 2 分钟新内容（或 400 个英文词、600 个汉字）更新一次，把上一版笔记和新的字幕片段一起交给 smart 模型，返回完整的新版 JSON：
  ```json
  {
    "sections": [{ "title": "小节标题", "start": "mm:ss", "points": ["要点"], "formulas": ["LaTeX"], "examples": ["例子"] }],
    "emphasis": [{ "text": "老师强调或可能考的点", "at": "mm:ss", "quote": "原话" }],
    "homework": [{ "text": "作业或要做的事", "due": "YYYY-MM-DD 或 null", "dueText": "原话里的时间" }],
    "terms": [{ "term": "英文", "zh": "中文", "explain": "解释" }]
  }
  ```
  主进程发 `notes:update`（`{ sessionId, notes, updatedAt }`），存进 `session.liveNotes`。失败或额度不够时保留上一版，界面上给一行小提示。
- **截取画面**：快捷键 `CommandOrControl+Alt+P`（可改）和界面按钮「截取画面」：截当前屏幕（网课课件）存进会议文件夹 `slides/<时间>.jpg`，记在 `session.slides`（`{ file, at }`），实时记录里对应位置显示缩略图。教室现场上课时可以用手机拍板书，这版不做手机同步。
- **课后笔记**：停止后「生成课堂笔记」（复用纪要按钮位置，课堂会议上叫「课堂笔记」），用课堂专用 prompt，输出简体中文 Markdown，术语保留英文，公式用 LaTeX：本节概览、大纲与知识点（按小节，带时间戳）、公式与推导、例子、老师强调和可能的考点、作业与截止、术语表（英文、中文、解释）、自测题 3 到 5 道（附答案）、没听清需要确认的地方。最多带最近 6 张截图给模型参考；笔记里在对应位置用相对路径引用截图。作业进待办（沿用 v3 的 items 机制，归到会议所属项目）。
- **导出**：会议详情里「导出到笔记库」：选一个文件夹（记住上次的，比如 Obsidian 库里的课程目录），拷一份 `课堂笔记.md` 和用到的截图过去，文件名带日期和标题。

## 四、界面

- 开始按钮的下拉：选项目、选模式（课堂再选声音来源）。项目页资料里可以设默认模式。
- 会议进行中视图随模式变化：课堂时右栏是「实时笔记」（小节大纲可折叠，强调点和作业单独一块，更新时有淡入，不抖动），顶部多一个「截取画面」按钮和快捷键提示；会议和面试时右栏仍是 AI 答题。
- 会议详情：课堂会议的标签页是 课堂笔记 / 字幕记录 / 截图 / 术语 / 作业。
- 设置：字幕与答题框分区加「意群颜色对照」；新增「课堂」分区：默认声音来源、实时笔记更新频率（1 / 2 / 5 分钟）、截取画面快捷键、导出文件夹。
- 首次引导不加步骤，只在最后一步提一句「上课可以用课堂模式」。

## 五、分工

- **X1 主进程**：enhance v2（prompt、parse、单测，engine 存 chunks）；模式和 `start({ projectId, mode })`；课堂的声音来源和「老师」标签；LiveNotes 模块（`src/main/class/liveNotes.js`）、截取画面（复用 `assist/screen.js`）、课堂笔记 prompt、导出；设置字段；IPC 和 preload；selftest 支持 `--mode=class`（配合 `--fake-mic` 当教室现场）。
- **X2 界面**：`src/renderer/shared/bilingual.js`；字幕窗接入意群颜色和中文 term 高亮；主窗口的模式选择、课堂进行中视图、课堂会议详情；设置里的新分区和开关；项目默认模式。

## 六、统一账号登录（全局规则 2026-09-24 新增）

> 2026-10-22 起不再登录：没有多端同步之前用不着账号，会员改用授权码激活。登录代码已从应用里删掉，留在 git 标签 `archive/account-login`（`git checkout archive/account-login -- src/main/account test/account.test.js` 拿回模块，界面部分看那个标签里的 control、settings、onboarding）。下面是当时的设计。

「给别人用的软件默认接共用账号系统，要登录」，会议字幕要给朋友用，所以接：

- Supabase 统一账号：Auth 用 Google 登录，PKCE。桌面端回调走 deep link `meetcaption://auth-callback`：`app.setAsDefaultProtocolClient('meetcaption')`，electron-builder 的 `protocols` 配好（Mac 的 CFBundleURLTypes、Windows 注册表都靠它）；Windows 上 deep link 从 `second-instance` 的 argv 里拿，Mac 从 `open-url` 拿。开发版（未打包）deep link 不可靠时，允许用本地回环 `http://127.0.0.1:<端口>/auth-callback` 兜底（前提是 Supabase 的 Redirect URLs 里允许）。
- 这个回调地址要加进 Supabase Auth 的 Redirect URLs：用 Supabase 的 access token 调 Management API 读出现有列表、追加、写回，别删掉别的产品的地址；改之前先把原列表备份到 scratch。
- 登录成功后调 `supabase.rpc('track_event', { p_product: 'meetcaption', p_name: '登录' })`。
- 实现参考已有产品：`~/Projects/relecture/docs/ARCHITECTURE.md` 第 5 节，GetNewWord / atrium 的登录代码（它们是 Swift，只借协议和流程）。主进程里用 `@supabase/supabase-js`（或直接调 Auth REST），session 存 userData（Mac 0600，Windows safeStorage），自动刷新。
- 首次引导第 0 步「登录」：Google 登录按钮，登录后显示头像和邮箱；设置的「账号与 AI」分区顶部显示当前账号和退出。没登录不能开始记录（开始按钮提示先登录）。
- 只用 anon key（公开），service key 绝不进应用。
- 验证：真实 Google 登录需要用户点，开发里用 Supabase Admin API（service key，只在测试脚本里、不进仓库）给测试用户生成 magic link 或直接建 session 走通「拿到 session → track_event → 退出」的流程；deep link 在打包版上用 `open 'meetcaption://auth-callback?...'` 模拟回调验证。
